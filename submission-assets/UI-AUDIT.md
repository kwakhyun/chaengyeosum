# 챙겨썸 TDS·UI 감사

감사 기준일: 2026-07-28  
대상: 로컬 개발 앱의 홈 → 새 모임 만들기 → 모임 상세 흐름

## 결론

종합 평가는 7/10이에요. 토스의 색상·보이스톤·간격 감각은 잘 따르고 있고 핵심 여름 모임 경험도 명확해요. 다만 현재 구현은 공식 TDS 컴포넌트를 사용했다기보다 TDS와 비슷하게 만든 커스텀 UI에 가까워요. 명백한 다크패턴이나 출시 차단 오류는 확인하지 못했지만, 실제 샌드박스에서 공통 내비게이션 중복과 컴포넌트 정합성을 먼저 확인해야 해요.

| 항목 | 평가 |
|---|---:|
| 토스 시각 언어 | 8/10 |
| 핵심 흐름 이해도 | 8/10 |
| TDS 컴포넌트 정합성 | 5/10 |
| 접근성 기본기 | 7/10 |
| 제출 완성도 | 7/10 |

## 잘된 점

1. 홈 첫 화면에서 `새 모임 만들기`가 바로 보여 핵심 행동을 찾기 쉬워요.
2. 토스 블루 `#3182F6`, `#191F28` 계열 본문색, 중립 회색을 일관되게 사용해요.
3. 버튼과 주요 조작 영역을 대부분 44px 이상으로 만들었어요.
4. 바텀시트는 제목·설명·닫기 버튼, 포커스 가두기, Escape 닫기, 이전 포커스 복귀를 구현했어요.
5. 진행률에 `progressbar` 의미와 현재값을 제공하고, 상태 메시지에 `aria-live`를 사용해요.
6. `prefers-reduced-motion`을 지원하고 장식 이미지는 빈 대체텍스트로 처리했어요.
7. 대부분의 문구가 해요체이고, 날짜·장소를 정하면 결과가 생긴다는 식으로 행동과 결과를 구체적으로 안내해요.

## 우선 개선점

### 1. 공통 내비게이션과 화면 안 브랜드 헤더 중복 — 높음

`granite.config.ts`는 로고와 앱 이름이 있는 공통 내비게이션을 켰지만 홈과 상세 화면에도 `챙겨썸` 브랜드 pill을 표시해요. 실제 토스·샌드박스에서는 로고와 앱 이름이 두 번 보일 수 있어요.

권장 조치:

- 실제 샌드박스에서 공통 내비게이션이 붙은 화면을 먼저 확인해요.
- 공통 내비게이션을 유지한다면 화면 안 브랜드 pill은 제거해요.
- 상세 화면의 홈 이동은 자체 브랜드 버튼 대신 공통 뒤로가기나 홈 정책으로 통일해요.

### 2. 커스텀 UI를 공식 TDS 구성으로 치환 — 높음

현재 `Sheet`, 모임 카드, 준비물 행, 하단 CTA를 모두 CSS로 직접 구현했어요. 커스텀 UI 자체가 금지되지는 않지만, 검수 일관성과 유지보수를 위해 공식 TDS 또는 앱빌더 결과물로 맞추는 편이 안전해요.

권장 치환 순서:

1. 하단 행동 영역 → `BorderBottomCTA` 계열
2. 모임 카드·준비물 행 → `ListRow`
3. 섹션 제목 → `ListHeader` 또는 `Top`
4. 안내·확인 레이어 → 공식 TDS 모달·시트
5. 보조 상태 → `Badge`, 주요 행동 → `Button`

### 3. 핵심 정보가 첫 화면 아래로 밀림 — 중간

375×812 기준 홈 히어로가 420px이라 기존 모임과 진행률이 첫 화면 아래에 있어요. 재방문 사용자는 새 모임 생성보다 현재 모임 확인이 더 중요할 수 있어요.

권장 조치:

- 히어로를 약 330~360px로 줄여 첫 모임 카드의 제목과 진행률까지 보이게 해요.
- 모임이 있을 때는 `내 여름 약속`을 위로 올리는 재방문형 홈 변형을 고려해요.

### 4. 하단 CTA가 긴 목록 뒤에만 있음 — 중간

상세 화면의 `준비 완료했어요`와 `진행률 공유하기`는 목록 맨 아래에 있어요. 준비물이 많으면 핵심 행동을 다시 찾기 어려워져요.

권장 조치:

- TDS 하단 CTA로 고정하거나 sticky 처리하고 safe-area를 유지해요.
- 주 행동 하나와 보조 행동 하나만 유지해 정보 밀도를 낮춰요.

### 5. 10~11px 보조문구와 낮은 대비 — 중간

준비물 수량·추천 이유 일부가 10~11px이고 `#8B95A1` 계열을 사용해 작은 기기에서 읽기 어려울 수 있어요.

권장 조치:

- 중요 보조문구는 최소 12~13px로 올려요.
- 흰 배경의 작은 본문은 `#6B7684` 이상으로 진하게 조정해요.
- 글자 확대와 실제 기기에서 줄바꿈을 확인해요.

### 6. 확대 비활성화 — 중간

`index.html`에 `maximum-scale=1.0, user-scalable=no`가 있어 사용자가 화면을 확대할 수 없어요. 앱인토스 런타임 요구사항과 충돌하지 않는지 확인한 뒤 가능하면 제거하는 편이 접근성에 좋아요.

### 7. 영어 보조 라벨 과다 — 낮음

`MY SUMMER`, `SMART PACKING`은 시각적 장식에는 도움이 되지만 토스의 간결한 한국어 보이스톤과 정보 우선순위를 약하게 만들어요. `내 여름 약속`, `날씨 맞춤 준비물`만으로도 의미가 충분해요.

## 다크패턴 점검

- 앱 진입 즉시 강제 바텀시트가 뜨지 않아요.
- 모든 바텀시트에 명확한 닫기 경로가 있어요.
- 이탈을 막는 인터럽트나 속이는 CTA를 확인하지 못했어요.
- 모임 생성·참여 과정에서 결제나 개인정보 동의를 숨겨 유도하지 않아요.

## 감사 한계

로컬 WebView 화면과 DOM을 기준으로 검사했어요. 실제 샌드박스의 공통 내비게이션, iOS·Android 글꼴 차이, 스크린리더 발화, 동적 글자 크기, 저사양 기기 성능은 아직 확인하지 않았어요. 따라서 완전한 접근성 준수를 보장하는 감사는 아니에요.
